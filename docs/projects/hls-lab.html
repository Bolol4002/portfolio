Overview

A hands-on High-Level Synthesis (HLS) laboratory series exploring how a C/C++ algorithm becomes a hardware architecture. The long-term target is a hardware accelerator for Sobel edge detection — implemented first as a software reference and then progressively transformed into optimized RTL with Bambu HLS, targeting the Basys 3 (Artix-7) board.

HLS Flow

  • C/C++ algorithm → Bambu HLS (schedule · allocate · bind) → generated Verilog RTL
  • RTL verified with Icarus Verilog / Verilator simulation against the reference implementation
  • Architectural optimization, then FPGA synthesis and implementation on the Basys 3

Laboratory Progression

  • Lab 0 — Adder · datapath / controller split, handshake (start_port / done_port)
  • Lab 1 — Vector Addition · loops, arrays, memory interface, resource sharing vs. parallelism
  • Lab 2 — MAC · multipliers, accumulators, DSP mapping
  • Lab 3 — FIR Filter · streaming computation, sliding windows
  • Lab 4 — 3×3 Convolution · the core structure behind Sobel
  • Lab 5 — Naive Sobel · correct hardware reference, not yet optimized
  • Lab 6 — Pipelined Sobel · target II = 1 (one pixel per cycle)
  • Lab 7 — Line-buffered Sobel · reuse rows to slash memory traffic
  • Lab 8 — Streaming / Optimized Sobel · dataflow, array partitioning, streaming interfaces
  • Lab 9 — FPGA implementation · Basys 3, BRAM-backed image, then UART/VGA

Sobel Edge Detection

Sobel operates on a 3×3 pixel neighborhood per output pixel, computing horizontal (Gx) and vertical (Gy) gradient convolutions and combining them as |Gx| + |Gy| — avoiding an expensive square-root — then saturating to an 8-bit output. The key hardware challenge is not the arithmetic but efficiently feeding the 3×3 window every cycle (line buffers, shift registers, sliding windows).

The emphasis of the project is the architecture: understanding how an HLS compiler's scheduling, pipelining and memory decisions change latency, throughput (II) and FPGA resource utilization.

Toolchain

  • Bambu HLS (PandA 2024.10) — C/C++ → Verilog
  • Icarus Verilog / Verilator — RTL simulation & linting
  • GCC / OpenCV — software reference implementation
  • GTKWave — waveform inspection
  • Vivado — final Basys 3 implementation

Status: environment set up, Lab 0 (adder) and Lab 1 (vector addition) verified in simulation.
